# CabLate 全站紙面風格轉譯計畫

## 1. 目的

紙面風格不是把每頁都加上紙條、手寫字或文具，而是讓網站像一套正在被使用、可以查閱與持續累積的工作檔案。全站保留紫色品牌、暖白紙面、細框、襯線標題與 Open Desk Archive 導覽；各頁再依任務選擇不同的敘事素材層。

這份計畫使用兩類實際參考：

- 使用者核准的桌機與手機 Open Desk Archive 基準圖。
- `references/current-pages/` 中八個主要頁面的目前實作截圖。

Imagegen 只產出介面提案與可拆解的素材方向，不直接取代真實產品畫面、客戶證據或 production UI。

## 2. 共用轉譯規則

### 不變項

- 桌機保留左側 Open Desk Archive rail；手機保留 CabLate 品牌列與完整選單。
- Accent 固定為 `#8064ea`，紙面 `#fffdf8`，外部背景 `#eeeae2`。
- 主要標題使用 Noto Serif TC 氣質；內文維持高可讀的 Noto Sans TC。
- 卡片只在資訊本身是可獨立移動的檔案、索引或證據時使用。
- 圖像不得生成假客戶、假課程現場、假 testimonial、假產品截圖或未授權人物。

### 可變項

- 紙張厚薄、分欄、標籤、裝訂、目錄、量測線、索引符號與資訊圖可依頁面任務變化。
- 敘事素材不限紙張：可使用工作台邊界、工具托盤、資料夾頁籤、校準刻度、流程線、影像接觸表、材料樣本或印刷標記。
- 每頁第一屏不能都是「小 eyebrow＋大標題＋一段文字＋按鈕」。至少改變標題位置、資訊密度、視覺錨點或入口形式其中兩項。
- 裝飾不得承擔必要文字；中文標題、CTA 與證據仍由 HTML 輸出。

## 3. 每頁轉譯

### Home｜入口桌面

- 任務：五秒辨識 CabLate，並讓訪客選擇學習、合作或作品。
- 保留：目前左右錯位的身份卡與原紫色有機主視覺。
- 紙面轉譯：把三條路徑做成桌面上的可掃描索引，不再增加另一張大圖；證據、方法與文章維持不同尺寸的檔案層級。
- 素材需求：主視覺沿用；後續可補一組非常淡的桌面印刷紋理與三個路徑識別標記。
- 手機：身份卡 → 路徑 → 主視覺，不能把桌機左右重疊硬縮小。

### About｜作者檔案

- 任務：說明 Cab 的專業如何形成，以及為什麼值得相信。
- 構圖：首屏改成作者檔案封面，不用與其他頁相同的 hero；Bio、身份關係與 dated proof 放在同一閱讀區。
- 敘事層：時間軸可像編年索引，公開作品像可查驗附件；正式 headshot 未提供前保留影像框，不生成虛構人物。
- 素材需求：未來使用真實 headshot；imagegen 只生成無人物的版型、光影、附件框與時間軸圖形。
- 手機：證據改成逐列定義，不把三欄數字壓成小字。

### Articles｜研究索引

- 任務：先依六個長期主題探索，再進入推薦起點與其他文章。
- 構圖：主題地圖是主視覺核心；推薦文章像被翻開的一份研究摘要，其餘文章是索引列，不做等寬卡片牆。
- 敘事層：可使用分類頁籤、註記刻度、文章狀態印記與引用線；不生成文章內容截圖。
- 素材需求：六個主題各一組可重用的簡潔符號，仍以 CSS／SVG 或小型透明素材為主。
- 手機：主題變成可掃描的單列索引，推薦內容維持完整標題與摘要。

### Courses｜學習路線

- 任務：依離成果的距離選擇免費資源、講座、課程或手冊。
- 構圖：不用商品牆；把四個階段做成路線／進度尺，清楚區分「可取得」與「未開放」。
- 敘事層：可以借用課綱分隔、進度標記、工具托盤或書背索引，但不可生成假課程封面與假上課照片。
- 素材需求：階段標記、狀態章、手冊真實封面或已核准產品圖。
- 手機：每個階段先顯示成果與適合情境，狀態文字不能看起來像可點擊按鈕。

### Services｜合作簡報

- 任務：讓合作方判斷需要診斷、訓練或導入，並理解邊界。
- 構圖：首屏像問題簡報封面；三種合作改成決策矩陣，不做服務卡片；流程與限制是同一份 brief 的不同頁。
- 敘事層：可使用風險刻度、流程連線、驗收勾選與需求欄位；匿名 proof 只顯示已核准的抽象文字。
- 素材需求：不需要人物照；優先以排版、線條與小型流程圖完成。
- 手機：決策矩陣拆成三個完整段落，Primary CTA 永遠是提交合作情境。

### Starter Pack｜已退役

Starter Pack 已從正式網站移除，不再生成頁面或投入新的紙面視覺資產。

- 任務：說清楚資源將解決什麼、適不適合，以及目前只是開放通知。
- 構圖：像一份尚在整理中的 starter kit 內容清單；狀態必須明確，不用「下載」視覺誤導已可交付。
- 敘事層：檢查表、內容清單、安全邊界與通知表單可形成一個工具包視覺；可以有收納格，不必全是紙條。
- 素材需求：日後資源完成後再加入真實封面與頁面預覽；現在只生成介面模板。
- 手機：四個問題與適合／不適合先於表單，Email label、確認信與隱私說明保持可見。

### Work｜證據桌

- 任務：用公開作品證明不同交付能力，並守住匿名與授權邊界。
- 構圖：代表作品像接觸表或證據清單；開源數字是 dated metadata，不做浮誇 KPI 卡。
- 敘事層：可使用檔案編號、repo 狀態、外部連結記號、影像框與證據來源線；有能力但未達 Case Study 的項目保留為 Project Note。
- 素材需求：優先使用真實 repo、產品與課程截圖；imagegen 只補版型和中性占位框。
- 手機：每件作品依序顯示類型、問題、作品說明、證據與目的地，不隱藏 proof 日期。

### Expertise｜方法圖譜

- 任務：說明六個長期主題與三個核心方法，並交代何時不該用 Agent。
- 構圖：六個主題做成可定位的研究圖譜；三個方法使用三種不同圖解語法，不是同款卡片換文字。
- 敘事層：可使用系統邊界、Context 流、Skill 觸發路徑、校準線與失效標記；避免科幻 HUD 或 AI 紫色光效。
- 素材需求：三張方法論圖解是最值得優先生成與拆解的資產。
- 手機：深連結抵達主題後，標題與 proof 必須同屏可讀；方法圖解改成直向，不縮成看不清的小圖。

## 4. Imagegen 生產順序

1. 先用 Home、About、Articles 產生三個不同頁型，確認整套紙面語言能變化而不分裂。
2. 再生成 Courses、Services，檢查決策型頁面是否仍清楚可用。
3. 最後生成 Work、Expertise，因為這兩頁更依賴真實截圖、證據與方法圖解。
4. 每一頁先產桌機長頁提案；方向通過後才產 390×844 手機版本。
5. 生成稿先存入 `docs/design/generated/<page>/`，經 review 後才拆成 production 所需的小素材或 CSS 元件。

## 5. 每張生成稿驗收

- 五秒內能辨識頁面任務與唯一 primary CTA。
- 與首頁共用同一導覽、色彩、字體與表面語言。
- 第一屏構圖不與其他頁機械重複。
- 沒有生成假的人、客戶、證言、課程現場或產品證據。
- 必要內容可由 HTML/CSS 完成；生成圖只承擔氛圍、圖解或敘事素材層。
- 能清楚標示哪些區塊沿用 production 內容、哪些只是提案。
