# 首頁改版 Session Reflection：供其他頁面直接套用

日期：2026-07-12  
適用範圍：About、Expertise、Work、Articles、Courses、Services、Starter Pack 與後續首頁微調。

## 這輪最後成立的方向

首頁不是素材總表，也不是產品功能牆。它的任務是讓訪客依序完成七件事：看見自己的問題、理解問題為何發生、知道 CabLate 的判斷立場、確認這個人是誰、選擇下一步、看到一個真實處理案例、決定是否留下更新通知。

視覺上保留 CabLate 的紫色識別、紙張材質、左側固定導覽與編輯感，但排版必須能用 CSS 穩定實作。真實照片用來補足信任與人物感，不再要求大量生成裝飾素材才能成立。

## Session 評估

- 成功做法：紙張表面與內容安全區拆開、逐段重寫閱讀旅程、用真實瀏覽器檢查標題換行與手機溢位、移除不真實的內容承諾。
- 主要摩擦：把「紙面排版參考」誤解為「全面換掉原品牌視覺」；先寫大量文案再塞版面；用裝飾層補救容器問題；只看程式碼而沒有持續看真實渲染。
- 系統性結論：後續頁面必須採用「先定頁面心理任務，再定段落與 CTA，最後套紙張元件」的順序，不能先畫一堆框再找內容填滿。

## 可重用的經驗

### 1. 紙面感是表面系統，不是內容排版理由

- 觸發：看到參考圖有紙條、圖紙或手寫註記時。
- 錯誤反應：直接把整站改成特定紙張拼貼風格，或為每個區塊硬塞裝飾物。
- 下次規則：先保留原品牌色、字體與主視覺；紙張只負責材質、邊緣、輕微層次和內容承載。裝飾素材必須有用途，沒有用途就不加。

### 2. `.paper-card` 與 `.paper-card__inner` 必須分工

- 觸發：文字靠近紙邊、超出背景，或為了顯示紙邊而縮放背景圖片。
- 錯誤反應：調整整張卡片 padding、用 overflow 隱藏，或在裡面再蓋一層白色容器。
- 下次規則：`.paper-card` 只畫紙張；`.paper-card__inner` 提供安全內距。桌機至少約 2.25rem，手機至少 1.25rem。任何可變文案都不得靠固定高度容納。

### 3. Mobile 的陰影與裝飾要獨立驗證

- 觸發：紙張下方看起來像多了一層深色底、角落露白或 pseudo-element 歪斜。
- 錯誤反應：繼續加陰影、邊框或絕對定位去遮。
- 下次規則：手機優先移除會形成大面積暗底的 `drop-shadow`；裝飾 pseudo-element 若不能與容器邊界精準貼合，就簡化或拿掉。材質不能以犧牲乾淨邊界換取。

### 4. 選單的紙張感來自外層紙面與內層安全區

- 觸發：手機選單內容凸出、紙邊被裁掉，或加內層背景後紙質感消失。
- 錯誤反應：放大背景到 102% 裁切邊緣，或在紙張裡蓋另一張不透明白卡。
- 下次規則：外層保留完整紙張材質，連結區在內部自然縮排；不要用第二層不透明背景遮住紙紋。按鈕、展開面板與桌機 rail 使用同一組 paper token。
- Mobile Headbar 也是紙張表面：背景圖必須略為放大以裁掉素材自身的透明紙邊，並由不透明 `--bg-soft` 托底，不能讓背景只覆蓋中央、左右或上下露出外層底色。

### 5. 標題不能只相信自動換行

- 觸發：中文標題在桌機或手機出現孤字、標點懸掛、語意斷裂。
- 錯誤反應：只加 `text-wrap: balance`，沒有看實際渲染。
- 下次規則：先寫出可朗讀的句子，再在重要標題使用受控 breakpoint 換行；每次至少看 1280px 與 390px。正文使用 `text-wrap: pretty`，但不把它當成內容編輯的替代品。

### 6. 每個區塊只承擔一個心理任務

- 觸發：同一區塊同時出現 Cab AI、互動簡報、課程、顧問、文章、訂閱數字等素材。
- 錯誤反應：因為素材存在就全部塞進首頁。
- 下次規則：先回答「讀者讀到這裡，應該理解什麼、感受到什麼、接著做什麼」。無法推進該任務的素材移到更適合的內頁。

### 7. 文案需要安排情緒與認知起伏

首頁成立的閱讀節奏是：

1. `這就是我遇到的問題。`
2. `原來不是我不會下 Prompt，而是流程不完整。`
3. `這個人有一套清楚的判斷。`
4. `我知道 CabLate 是誰，也知道他在意什麼。`
5. `我可以依自己的情境選入口。`
6. `這套方法確實用在真實問題上。`
7. `我願意在有重要更新時再回來。`

後續頁面也要有自己的起伏，不能一路列能力、列產品、列數字。

### 8. 身份與證據要放在讀者需要的位置

- `我是 CabLate` 必須是可掃讀的身份轉折，不應埋在第二段灰字裡。
- 數字不是愈多愈可信。像講座評分若和當下決策無關，放進段落只會突兀。
- 案例證據應跟著案例 CTA，而不是另做一張與故事搶焦點的「旗艦知識產品」卡。
- 品牌副標若不能幫助定位，就不要佔用 Headbar 空間；`Open Desk Archive` 因此移除。

### 9. 不承諾已經停止的內容節奏

- 部落格很久沒更新，就不在首頁做「推薦閱讀」假裝持續出版。
- 電子報只剩通知用途，就直接寫「有重要更新時，再寄信告訴你」，不承諾固定週期。
- 信任不是靠寫得熱鬧，而是公開承諾與實際營運一致。

### 10. 真實照片比無目的概念圖更能補足信任

- 首頁輪播只保留兩張真實活動照片。
- 第一張是 LCP：`loading=eager`、`fetchpriority=high`。
- 第二張是隱藏投影片：`loading=lazy`、`fetchpriority=low`。
- 圖片先轉 WebP、保留明確 width/height，再在桌機正方形與手機 4:3 實際檢查人物裁切。
- 輪播分頁的數字與圓點必須有固定 inline allocation，避免切換時左右抖動；不自動播放。

### 11. HMR 畫面不一定代表目前程式碼

- 觸發：commit 看似正確，但瀏覽器突然顯示舊版或 CSS 宣告缺失。
- 下次規則：先比對原始 HTTP HTML/CSS、computed style 與全新分頁；必要時等待 View Transition 結束再截圖。不要在快取或 HMR 狀態不明時立刻回滾正確程式碼。

### 12. Checkpoint 必須在使用者確認畫面後立即建立

- 觸發：準備進入大幅文案或版面重構。
- 下次規則：先確認工作區變更集合、建立 checkpoint、確認無意外未提交程式碼，再開始下一輪。回復時以該 checkpoint 與實際工作區為準，不能只憑記憶猜測。

## Class 責任模型

後續頁面採四層責任，不再任意複製 CSS：

1. 全站 token：色彩、字體、陰影、紙張圖片。
2. 共用元件：`.paper-card`、`.paper-card__inner`、`.paper-card--clip`。
3. 共用 utility：`.section-label`、`.text-link`、`.btn`、`.btn-primary`。
4. 頁面 class：只描述該頁真正不同的 grid、段落或互動，例如 `.diagnosis-layout`。

如果一個 class 沒有 CSS、JS、測試定位、無障礙或語意責任，就不應只為「幫區塊取名字」而存在。

## 其他頁面的處理順序

每次只處理一頁，依下列順序：

1. 定義這一頁唯一的訪客任務與主要 CTA。
2. 刪除過期承諾、重複導覽與素材清單式文案。
3. 規劃 4–7 個閱讀節點，寫出每段的「理解／感受／下一步」。
4. 先用完整自然句完成文案，再決定標題換行。
5. 套共用紙張安全區、標籤與連結 class。
6. 只為該頁特殊布局建立 page-specific class。
7. 在 1280 × 900 與 390 × 844 檢查首屏、完整閱讀、紙邊、換行、CTA、選單與水平溢位。
8. 執行 `git diff --check`、`npm run check`、`npm run build`，更新對應契約與截圖證據。

## 文案 Review 問題

每個區塊交付前都要回答：

- 訪客讀之前在想什麼？
- 這段只想讓他理解哪一件事？
- 讀完後情緒是更安心、更好奇，還是更能做決定？
- 這裡真的需要 CTA 嗎？如果需要，只推哪一個動作？
- 是否重複了導覽、前一區或其他頁面已經說過的內容？
- 是否用了實際沒有持續提供的承諾？
- 證據是否直接支撐當下決策，而不是單純展示數字？

## 完成門檻

- 一頁只有一條主要閱讀主線，不是素材堆疊。
- 每個紙張區塊有安全內距，可承受文案增加與 200% zoom。
- 標題在桌機與手機沒有語意破碎的換行。
- 共用視覺使用共用 class；頁面 class 有明確責任。
- 沒有水平溢位、console error、過期承諾或假證據。
- 契約、文案規範、實際畫面與程式碼一致。
