# CabLate.com 全站目的、頁面角色與 CTA Master Plan

## 1. 這個網站最終要完成什麼

CabLate.com 不是履歷、工具收藏、文章倉庫，也不是把所有產品放在一起的銷售頁。它是一個公開的信任與決策中樞。

網站的總目標是：

> 幫助正在使用 AI、卻遇到失控、反覆重做或無法交付的人，看清問題卡在哪裡；讓他理解 CabLate 能把複雜問題整理成可使用、可檢查、可持續的下一步，最後選擇適合自己的內容、學習資源或合作方式。

這個目標包含四層價值：

1. **內容價值：看清問題。** 訪客知道 AI 成果不穩不一定是模型或 Prompt 的問題，也可能是任務、資料、工具、權限、完成標準與復原方式沒有接好。
2. **品牌價值：相信判斷。** 訪客相信 CabLate 不只會操作工具，也能辨認問題、說明限制、選擇合理做法並留下可檢查的成果。
3. **轉換價值：選擇下一步。** 不同成熟度的訪客能前往問題診斷、文章、學習路線、工程手冊、作品或合作評估。
4. **信任價值：不做錯誤推銷。** 不把每個問題都說成需要 Agent、課程或顧問；免費內容足以解決時，就讓訪客先從免費內容開始。

## 2. 商業目標與成功條件

商業目標不是單純增加按鈕點擊，而是：

> 把來自搜尋、社群、演講與口碑的陌生訪客，逐步轉成理解並信任 CabLate 判斷方式的人；讓其中具有明確需求的人進入適合的學習產品或合作評估。

高品質轉換應符合：

- 不適合付費的人能從公開內容得到答案。
- 還不清楚問題的人先學會辨認現象，而不是立刻被推銷。
- 適合手冊的人不必先閱讀企業服務。
- 有具體作品或團隊問題的人能帶著足夠資訊前來。
- 企業訪客能快速理解合作結果、投入條件與責任邊界。
- 暫時不需要行動的人，只有在真正重要的更新出現時才收到通知。

## 3. 品牌核心與差異化

核心主張：

> 判斷力比執行力值錢。

對訪客的白話翻譯：

> AI 執行得愈來愈快，但如果任務、資料、工具與完成標準沒有接好，只會更快走錯方向。CabLate 的工作，是先看清問題，再把合理做法整理成能使用、能檢查、能交接的流程。

CabLate 不是「更多 AI 工具」的介紹者，差異在於：

- 從失效現象往回診斷，不先假設解法。
- 工具、Prompt、Agent、Skill、Context 都只是手段。
- 交付必須能被使用、驗收、重現與接手。
- 實際經驗、研究判斷與尚待驗證的想法要清楚區分。
- 簡單方法足以解決時，不為了熱門名詞增加架構。

## 4. 全站共用的訪客情緒主線

CabLate 不靠 FOMO、焦慮或誇張效率承諾推動。理想路徑是：

```text
被理解
→ 鬆一口氣
→ 看見新的問題解釋
→ 覺得問題可以被拆解
→ 用真實證據建立信任
→ 採取一個小而明確的行動
```

每個區塊都必須回答：

1. 訪客讀之前在想什麼？
2. 這段只讓他理解哪一件事？
3. 哪個擔心因此變小？
4. 讀完後應更願意做哪一步？

答不出來的段落通常只是資訊，不是有效文案。

## 5. CTA 的定義與規則

CTA（Call to Action）是希望訪客接著採取的行動。它不只是按鈕文案，而是一個區塊希望訪客完成的下一個決定。

CTA 分為三層：

- **Primary CTA：** 該頁唯一的主要決策。
- **Secondary CTA：** 不準備採取主要行動時的合理替代路徑。
- **Contextual CTA：** 跟著案例、方法或文章出現，只延伸當下內容。

規則：

1. 一頁只有一個 Primary CTA 意圖，可以在頁首與頁尾重複，但不能換成另一個目的。
2. CTA 要描述訪客會前往哪裡或完成什麼，不寫空泛的「了解更多」。
3. 先建立理解與適配，再要求購買、聯絡或訂閱。
4. 同一畫面不能出現兩個語意相同、互相競爭的主要按鈕。
5. 外部平台 CTA 要說明目的，例如「到 Threads 說明你的情況」，而不是只寫平台名稱。

## 6. 三條主要訪客旅程

### 6.1 還不知道問題在哪

```text
Home
→ Expertise
→ 對應 Articles
```

目標：從「AI 就是很不穩」走到「我知道先檢查資料、工作環境或可重複方法中的哪一層」。

### 6.2 想自己建立能力

```text
Home
→ Courses／學習路線
→ 免費文章、問題診斷或深度工程手冊
```

目標：只選現在需要跨過的一步，不因產品階梯而一次購買過多內容；不提供已退役的 Starter Pack 入口。

### 6.3 已有具體作品或團隊問題

```text
Home
→ Work
→ Services
→ 提交合作情境
```

目標：先確認 CabLate 的判斷與交付方式，再提供現況、限制與期望成果進行適配評估。

About 是信任補強頁，不是每條旅程都必經的轉換漏斗。

## 8. 頁面分工細則

### Home

保留問題辨識、核心主張、身份、三條路徑與一項代表性證據。首頁不教授完整方法，也不重複 Expertise 的診斷框架。

### About

用少數轉折解釋 Cab 為何在意交付、驗收與可持續使用。作品只作人物故事的證據，完整案例留給 Work。

### Expertise

不是方法名稱清單，也不是首頁診斷區的長版。每套方法應提供：現象、先檢查什麼、常見誤判、適用邊界與對應文章。

### Work

每個案例回答問題、限制、角色、關鍵判斷與可公開結果。公開限制放在對應案例旁，不集中成頁尾免責聲明。

### Courses

對外定位為「學習路線」，即使保留 `/courses/` URL。主角是目前可採取的內容；未開放狀態只作簡短說明，不占主要視覺層級。

### Services

先說完成後的工作狀態，再區分個人／小團隊診斷、團隊內訓，以及產品／Agent 導入。清楚說明三種合作是否可銜接及各自需要的前置條件。

### Articles

以問題路徑作主要索引，分類與標籤為次要工具。同一篇文章不應同時出現在「問題路徑、推薦起點、文章列表」三層重複曝光。

## 9. 全站視覺系統與各頁視覺語法

各頁共享同一套 CabLate 品牌系統，但不能因此成為同一份紙卡版型。共用層負責紫色識別、紙張材質、字體、基本元件、安全內距與響應式規則；頁面差異則由資訊結構、版面節奏、內容層級與少量具有用途的裝飾建立。

七個主要入口頁的視覺語法如下：

| 頁面 | 視覺語法 | 版面任務 |
|---|---|---|
| Home | 敘事與分流，版面變化最多 | 用不同節奏完成問題辨識、人物建立、路徑選擇與代表性證據；它是全站入口，不是其他頁面的縮圖集合。 |
| About | 人物故事與時間軸，像翻閱工作筆記 | 用時間、轉折、照片、註記與代表作品形成閱讀推進，讓經歷支持判斷方式，而不是堆成履歷卡片。 |
| Expertise | 診斷表與方法對照，像問題排查文件 | 讓症狀、檢查順序、常見誤判、適用邊界與延伸閱讀可以橫向比較和快速掃讀。 |
| Work | 案例檔案，一件作品一份摘要 | 每件作品使用穩定的檔案結構呈現問題、限制、角色、關鍵判斷、結果與揭露範圍，避免只靠圖片或作品名稱。 |
| Courses | 階段路線與選擇比較，像學習地圖 | 呈現不同起點、深度、適合情境與下一步，協助訪客選擇剛好的學習路徑，而不是把內容排成商品牆。 |
| Services | 情境、成果、合作流程，像合作簡報 | 依序回答適合誰、完成後留下什麼、需要哪些投入、如何進行及有哪些邊界，使訪客能自行判斷適配程度。 |
| Articles | 問題索引與閱讀入口，像編輯目錄 | 先按真實問題建立閱讀路徑，再提供次要分類與完整列表，讓訪客快速找到起點而不是瀏覽無差別卡片。 |

視覺實作遵守以下邊界：

- 首頁可以有最多的版面變化，但仍須維持清楚的閱讀順序。
- 內頁以各自任務建立辨識度，不為了「看起來不同」發明無用途的裝飾。
- 紙張、迴紋針、標籤或註記必須協助分組、定位、比較或建立敘事，不作隨機點綴。
- 共用紙張容器只管理材質、邊界與安全內距；局部版面不能破壞內容安全範圍。
- 不依賴大量生成圖片才能成立，優先使用可維護的 HTML 與 CSS 完成資訊層級。
- 手機版不是桌機版的縮小版，必須重新確認閱讀順序、標題斷句、觸控區域與紙張邊緣。
- 各頁可以有不同密度與節奏，但不能改變紫色品牌識別或讓訪客誤以為進入另一個網站。

## 10. MadeByPan 的借鑑邊界

### 值得借

- 用讀者語言說出卡住的時刻。
- 先給容易重述的新解釋，再介紹專有名詞。
- 讓產品代表一段進展，不是一包內容。
- 每頁提供低理解成本的下一步。

### 不應借

- 十倍、百倍、每日省時等缺少 baseline 的承諾。
- 把案例、贈品、課綱、比較與 FAQ 不斷疊加成巨大銷售頁。
- 用作品數量代替問題、限制與判斷過程。
- 用圖片承擔唯一的重要文案，犧牲可及性、搜尋與維護。
- 因為有產品就讓每位訪客都進入銷售路徑。

## 11. Content OS 素材調用閘門

任何素材進入頁面前，必須通過：

1. 這頁只負責哪一個決策？
2. 訪客在這個位置擔心什麼？
3. 素材能改變哪個信念或降低哪個風險？
4. 它扮演主張、解釋、故事還是證據？
5. 同一角色是否已有更強素材？
6. 是否在其他頁重複使用？主要歸屬頁是哪裡？
7. 是否有公開授權、來源與日期？
8. 讀完後要把訪客帶去哪一步？

CabAI、Interactive Engine、GitHub、npm、多 Agent 系統等名稱只有在能支撐當下主張時才出現。素材存在，不等於必須曝光。

### 11.1 CabAI 在個人網站中的長期角色

CabLate 個人網站負責讓陌生訪客認出問題、理解方法並建立信任；CabAI 負責免費試看、商品比較、建立帳號、購買、內容交付與 Discord 會員身分。兩站不是重複首頁，而是前後相接的理解與交付系統。

- Home：訪客理解問題與方法後，才提供一個低壓力的 CabAI 內容總入口；不放進 Hero 搶走診斷任務。
- Courses：CabAI 商品、免費試看與帳號是主要轉換；必須連到具體商品或明確帳號用途。
- Articles：依文章問題推薦 AgentSkill 或工程手冊；無法對應時回到站內學習路線，不硬推商品。
- Work：CabAI 用來承接可公開檢查的商品、內容與交付結果，不先要求購買。
- About：CabAI 是能把知識產品做成交付系統的證據，只保留低權重入口。
- Services：合作提交與 CabAI 商品分開，不用低價商品干擾企業合作判斷。
- 全站 footer／側欄：CabAI 可作生態導覽，但不能成為每頁的 Primary CTA。

跨站 CTA 必須說明目的，例如「查看課程與免費試看」「建立免費帳號，保留購買內容」「建立帳號並連結 Discord 社群」。不能只寫「CabAI」「註冊」或「加入 Discord」，讓訪客到了外站才猜下一步。

商品連結應直接進入商品詳情，不先繞回 CabAI 首頁；跨站 URL 要帶來源參數，以區分 Home、Courses、Work 與 Articles 的實際貢獻。

合作 Email、更新通知、CabAI 帳號、Discord 身分與商品購買是五種不同資料用途，不得互相默認共用。公開聯絡信箱以 `src/config/siteConfig.ts` 為唯一來源；更新通知只承諾重要更新，不承諾固定電子報頻率。

## 12. 公開證據與誠信原則

- 不公開營收、客戶機密、未授權姓名、Logo、照片、原話與內部資料。
- 動態數字附日期，不寫成永久事實。
- 無法公開完整結果的合作，只說可驗證的範圍、角色、日期與揭露限制。
- 不用 Cab 自己的形容詞替代證據，讓事實本身支持判斷。
- 沒有持續更新的部落格、電子報或產品，不創造固定頻率承諾。
- 不保證營收、流量或尚未定義的商業成果。

## 13. 文案與視覺原則

- 先說人能辨識的問題，再說 Harness、Context、Skill、Agent 等名稱。
- 專有名詞第一次出現時要用一句白話說明。
- 一個句子承擔一個主要意思。
- 各頁不能都使用同一套「你不需要／先／問題不只是」句型。
- 標題先寫成可朗讀的自然中文，再用 `text-wrap: balance` 輔助；不能只相信自動換行。
- 紙張是品牌表面，不是堆疊更多區塊的理由。
- 每頁保留自己的敘事語法：人物歷程、診斷表、案例檔案、學習地圖、合作簡報、編輯索引。

## 14. 持續審查準則

新增、重寫或重新設計頁面時，都必須確認：

- 五秒內能否知道這頁與訪客有何關係？
- 是否只有一個主要心理任務與 Primary CTA？
- 是否重複其他頁面已負責的解釋？
- 每個證據是否緊鄰它支撐的主張？
- 拿掉某個產品或工具名後，敘事是否仍成立？
- 是否存在因為「我們有素材」而硬加的段落？
- 頁面是否符合自己的視覺語法，同時仍能辨認為 CabLate 品牌？
- 桌機與手機是否都有自然換行、安全內距、清楚閱讀順序與零水平溢位？
- 互動、連結、鍵盤操作、可讀性與建置品質是否經過實際驗證？

這份文件是後續全站文案、CTA、內容選擇與頁面視覺分工的主要決策基準。若實際產品狀態、公開授權或商業方向改變，應先更新這份文件，再修改頁面。
