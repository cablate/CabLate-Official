你絕對遇過這種很煩的情況：想叫 AI 幫自己網站找漏洞，一提到滲透測試就被直接拒答，最後只好一直編劇本跟它討價還價。這篇整理 OpenAI Daybreak 的最新申請門檻、獨立靶機配置與避坑做法，帶你正大光明安全開掃。

我現在的做法很單純，就是先拿許可，再進練習場。我去申請 OpenAI Daybreak 計畫，再用開源工具 Strix 接上 OpenAI GPT-6 系列裡的 Sol 當主模型、Luna 當子代理去打自己的靶機，token 花約 110 美金就拿到完整資安報告，以資安檢測來說其實很便宜。

## 動手前先把授權講死：絕不讓 AI 碰正式站

在複製任何指令之前，安全底線一定要先畫出來。OpenAI Cyber Abuse Policy 與 Strix 的「Authorized use only」都寫得很明白，這套工具只能測自己擁有或取得書面授權的系統，沒有授權的目標一律不准碰。

就算是自己的服務，也絕對不要讓 AI 直接打正式站！請另外架一台不連任何正式資料的獨立靶機當練習場，就算測試過程把環境打壞，整台刪掉重建就好，不用每天提心吊膽擔心線上資料出事。

## Daybreak 申請門檻變了：實體 FIDO2 金鑰才算數

這條官方資安授權線現在越來越像標配了。2026 年 11 月 12 日 OpenAI 剛擴充 Daybreak，推出了兩款 agentic 產品：做 Web 應用滲透測試的 Daybreak Red Team，以及自動掃碼並草擬修補 PR 的 Daybreak Defense Factory。

不過現在去 `chatgpt.com/cyber` 申請已經改成整體審核，以前很多取巧方法走不通了。送件前先把下面三道硬門檻湊齊，才不會卡在驗證來回重跑：

1. **滿 18 歲並綁定合格付費方案**：這是送審的基本門檻，免費帳號沒辦法申請這條通道。
2. **開啟 Advanced Account Security（AAS）**：這個高強度保護打開後，系統會停用原本的密碼與簡訊登入，避免帳號被撞庫搶走。
3. **準備至少一支實體 FIDO2 金鑰**：現在用軟體模擬或手機、電腦同步的 passkey 已經不算數，而且 TrustKey T110 與 T120 也不符資格，買之前要先看清楚型號。

這裡順手更正我早期的說法：以前我曾經建議過用雙 passkey 就能過關，但現在官方規則已經收緊，這招不能用了。請直接以現行規定為準，買好符合資格的實體金鑰再送件，省得白跑一趟。

## 我現在怎麼配 Strix：先 clone 再讓 AI 改設定

拿到許可之後，練習場我搭配的是開源工具 Strix。它採用 Apache-2.0 授權，截至 2026 年 11 月已經破 6 萬 stars，整套跑在 Docker 容器裡，會自主掃描目標並用 PoC 驗證漏洞後再輸出報告。

先把環境裝起來並設定好預設模型與金鑰，執行前記得確認本機的 Docker 已經啟動，下面三行指令可以直接複製去跑，把最後一行的 API Key 換成你自己的就好：

```bash
curl -sSL https://strix.ai/install | bash
export STRIX_LLM="openai/gpt-6.1-sol"
export LLM_API_KEY="你的_API_Key"
```

不過這裡有個很容易踩到的坑：`STRIX_LLM` 預設只能填單一模型名稱，如果你想像我一樣把主模型跟子代理拆開，只跑上面那行安裝指令會讓 AI 找不到本地文件。要讓 AI 改寫模型設定，需先 `git clone` 官方 repo 下來並確認 Docker 已啟動，再進專案目錄作業。

我的做法是請 AI 直接修改配置，把主模型設為 OpenAI GPT-6 系列的 Sol、子代理設為 Luna，同時檢查 API 請求有沒有帶上 `access_programs.cyber` 參數。至於環境變數與 API 端參數的細部寫法，還是要以當時官方文件為準。

下面這段現成提示詞可以直接貼給 AI 去改，記得叫它改完先列出修改位置跟啟動方式，再次確認目標是指向獨立靶機、沒有連到正式站再開跑：

```text
請閱讀 Strix 的 README 與設定文件，幫我把測試目標設定為我的靶機網址（確認不要連到正式站），並修改 Strix 的模型呼叫配置：將主模型設為 GPT-6 Sol，子代理設為 GPT-6 Luna，並確認 API 請求有帶上 Daybreak 的 `access_programs.cyber` 設定。改完先列出修改位置與啟動方式給我看。
```

## 過審還是可能被擋？看懂 Blue 與 Red 的三道邊界

很多人以為過了 Daybreak 審核就能從頭掃到尾，結果跑起來還是照樣吃閉門羹！其實官方背後還畫了明確的權限分級與審查機制，實務上一定要先看懂這三道邊界：

1. **Blue 與 Red 權限分級不同**：程式碼審查、弱點分級屬於 Blue；攻擊型的滲透測試、紅隊與 exploit 驗證屬於 Red，必須另外核准。實務上就算你拿 Blue 權限去跑 Strix 掃描，遇到部分偏攻擊性的請求還是可能被攔下來。
2. **不同模型的降擋範圍有差**：在 Blue 權限下，主要是 GPT-6 Sol 與 GPT-6 Luna 會降低拒答率；如果你想讓 GPT-6 Astra 也降擋，必須拿到 Red 權限才會放行。
3. **高風險與模糊請求照樣擋**：資安研究者 Ian Carroll 在 11 月 5 日實測授權研究與漏洞利用時，一樣常被 Daybreak 與 CVP 擋下，最後只好改用 DeepSeek 與 GLM 5.3 繼續測。

如果你的測試情境真的需要完全無阻攔的環境，與其一直跟審核邊界耗時間，實務上直接換模型更快。通常可以改選中國開源模型，例如 Qwen 3.8 或 GLM，不然就是自己架地端模型來跑，才不會掃到一半卡死。

把安全規則跟邊界先踩穩，AI 資安掃描才走得長久。你只要把實體 FIDO2 金鑰備齊過審、把練習場徹底跟正式站隔離，再依照手上的權限等級選對模型或備案，就能穩穩用這套流程替自己的服務抓漏。
