你叫 AI 做網站，它很快產出頁面，看起來也能打開。接著才發現首頁塞了用不到的功能、配色不一致，或文章頁缺了搜尋資訊。畫面出來只是開始，動手前少做的決定、做完沒跑的檢查，最後都要回頭補。

2026 年初我用 Claude Code 建 CabLate 官網，先定好用途與結構，再讓 AI 按區塊實作；後來把深色遊戲風改成淺色主題時，更確定規格清楚的重複修改適合交給 AI，方向和驗收仍要人負責。

## 開始寫之前，要先決定甚麼？

**先定好網站用途、部署方式與專案結構。** 當時我要放文章與作品集、優先產生靜態頁面、能使用元件，並部署到 Cloudflare Pages，對照後選了 Astro。選框架要跟專案條件一起看，不能只看一張新舊版本混在一起的比較表。

接著切專案結構：文章放 `src/content/articles/`，版面放 `src/layouts/`，頁面區塊與共用元件分開。AI 能幫忙提架構，但好不好維護要自己確認。結構定好，下一步才是把需求拆給 AI 寫。

## 怎麼把需求交給 AI，才看得出哪裡要改？

**把頁面拆成能單獨檢查的區塊，逐一給明確規格。** 比起只丟一句「幫我做完首頁」，先講清楚元件名稱、要接的資料、預期畫面與 CSS 變數，做完才容易對照需求找出缺漏。

SEO 也一樣。meta tags、社群預覽、結構化資料、RSS、sitemap 和文章路由可交給 AI 處理，但網站寫給誰、回答甚麼問題仍要我決定；建好後再用實際頁面與檢查工具確認輸出，不能只看 AI 的完成訊息。單一區塊能這樣拆，那如果要改全站風格呢？

## 大範圍改版，甚麼適合交給 AI？

**範圍大、規則一致的重複修改，特別適合交給 AI。** 當時我把深色遊戲風格改成淺色，涉及 4 個全域 CSS 檔案與 7 個元件的樣式，並移除金色、發光與漸層效果。原紀錄估計手動修改約需半天，AI 約十分鐘完成；這是當時的個人估計，不是不同專案都能達到的速度。

能這麼快，是因為我先決定要改成甚麼樣，再讓 AI 依規格改完多處相同的樣式；但完成後仍要看頁面，確認共用樣式改動沒有影響其他區塊。想進一步看人與 AI 的分工，可接著讀〈[你可能不需要龍蝦：自動化跟 Agent 是兩件事](/articles/blog-writing-openclaw/)〉、〈[AI 取代工作？從 Anthropic 雷達圖看理論與現實的落差](/articles/anthropic-radar-ai-cannot-replace/)〉與〈[寫了 Skill 卻死都不觸發？拆解 CLAUDE.md、Skill 與 MCP 的分工](/articles/claude-code-skill-vs-claude-md-and-mcp/)〉；若要把本文的判準用在自己的工作，可參考[AI 工作流健檢](/expertise/)的適用範圍。

## AI 給了結果，怎麼知道能不能交付？

**拿原本的需求逐項核對畫面、內容與連結。** AI 能幫忙找建置錯誤和 CSS 衝突，但也可能自己加進不需要的功能，或在長對話中漏掉先前的限制。頁面打得開只是起點；文章找不找得到、預覽資訊對不對、手機上好不好讀，都要按專案需求實際檢查。

就算測試通過，也要看它到底檢查了甚麼。我在[另一篇文章](/articles/ai-tests-false-safety-six-phase-overhaul/)拆過為甚麼全綠仍可能漏掉重要的問題。

下次讓 AI 做網站，先寫下三件事：這個網站要給誰用？這一輪完成後該看到甚麼？你要怎麼確認結果符合需求？
