你剛學會一套 Agent，下一個框架又紅了。它也說會記住你、會用工具、會主動工作，於是你又開始看安裝教學，重新認識一套名稱。

我看到 OpenClaw 的架構介紹時，心裡馬上浮現「這不就是我在做的東西嗎？」

在 ChatGPT 推出 Deep Research 之前，我就自己做過一個 Deep Research：讓語言模型拆問題、呼叫搜尋工具、整合結果，再歸納。後來又做了一套 Telegram 多代理系統 ClaudeCab，裡面有秘書、寫手和工程師，各自有指令、工具與記憶。

這些是我在 2026 年 3 月文章裡公開的實作經驗。它們讓我覺得，學新框架時最有用的起點，是先認出它把哪些已知能力接在一起。**工具會換，查指令與資料怎麼進出的能力可以帶走。**

## OpenClaw 整合完整，就代表底層全是新的嗎？

**整合本身有價值，但不能只靠功能名稱判斷底層原理。**

OpenClaw 把通訊介面、模型、工具、記憶與持續運作接起來，省下使用者自己拼接的工。這種差異很實際，不需要因為其中用了既有概念就否定它。

不過，如果你已經做過工具呼叫與對話管理，看到新框架的「記憶」和「主動工作」，就可以繼續問：記憶存在哪裡，下一輪誰讀？工作是誰觸發，甚麼時候停止？

李宏毅教授曾用 OpenClaw 說明 Agent 運作，想看完整講解可以看[這支影片](https://youtu.be/2rcJdFuNbZQ)。以下是我為了對照實作整理的五個問題；它們是一種拆解方法，並非所有 Agent 都遵守的固定五層標準。

## 「它知道要怎麼做事」，指令從哪裡來？

**先看執行環境在呼叫模型前組裝了哪些指令。**

模型收到的內容，可能包含 system prompt、角色規則、使用者資料與當次任務。同一個模型，因為收到不同指令和資料，表現就可能不同。

在我當時的 ClaudeCab 裡，秘書、寫手、工程師有各自的設定。要查寫手為甚麼照工程師的方式回覆，第一步就是確認實際讀入哪份設定，而非立刻換模型。

這裡的「為甚麼照另一個角色回覆」是排查示例。不是每次角色不合預期都源於設定檔，也不表示只要放一份指令就能穩定執行。

## 「它能做動作」，誰真的執行了？

**模型選擇或提出工具呼叫，執行環境才會去執行工具。**

模型可以輸出搜尋、讀檔或寫入的請求；外層程式驗證參數、檢查權限、執行動作，再把結果送回模型。模型說「已經寄出」與郵件服務確實寄出，是不同的證據。

所以 Agent 回你「做不到」時，要看工具是否有提供、說明是否清楚、呼叫是否失敗。Agent 回你「完成」時，則要去看工具結果與目標資料有沒有改。

MCP 能協助工具連接，但它不會替你決定每個工具何時應該使用，也不會讓所有操作自動獲得授權。

## 「它記得我」，資料到底存在哪裡？

**保存與讀回必須同時存在，記憶才能在下一輪派上用場。**

對話歷史可以提供近期脈絡；長期資訊則可能寫進 Markdown、資料庫，或其他儲存系統。寫進去之後，還要有自動載入、搜尋或讀取的路徑。

以 2026-10-29 查閱的 [OpenClaw 記憶文件](https://docs.openclaw.ai/concepts/memory)為例，它會使用工作區的記憶檔案，也提供搜尋與讀取工具。不是目錄裡所有檔案都會在每輪全文加入；自動載入還有內容預算，過長的檔案可能只載入一部分。

因此「我明明寫進 memory 了」還沒排除問題。可以再查那筆資料是否保存成功、這次有沒有讀到，以及讀到的版本是否仍有效。

## 「聊久了就忘記」，哪一段上下文變了？

**先查舊對話如何被摘要或裁切，以及需要的資訊是否進入這次請求。**

Context window 有限，執行環境會管理模型每次看得到的內容。較舊的對話可能被整理成摘要，過長的工具輸出可能縮短。磁碟上仍有完整紀錄，也不代表模型當輪看得到全文。

[OpenClaw 的壓縮文件](https://docs.openclaw.ai/concepts/compaction)說明，較舊對話會被摘要，近期內容保留；也有壓縮前保存持久資訊的安排。

要排查遺漏，拿一件具體沒接上的事去查。例如上輪決定的交付格式，還在摘要或已讀回的狀態檔裡嗎？比起要求「永遠記住所有事情」，這樣比較找得到發生在哪一步。

## 「它會主動工作」，是誰把它叫醒？

**先查觸發來源，再查觸發後帶入的任務。**

Agent 可以由新訊息、排程、外部事件或背景工作完成來觸發。觸發後，系統組裝輸入、呼叫模型，模型才開始判斷下一步。

原文用 Heartbeat 定時喚醒來說明這件事。這個名稱已經不能照舊教：2026-10-29 查閱的 [OpenClaw 文件](https://docs.openclaw.ai/gateway/heartbeat)說明，原先 heartbeat monitor 已改由一般 automation jobs 承接。

名稱改了，排查仍可以落在具體位置。沒準時做，是排程沒啟動、工作沒收到，還是執行失敗？準時啟動但做錯，則要回到指令、資料和工具查。不能把每種失敗都叫成模型不夠聰明。

## 換框架時，怎麼把已學會的東西帶過去？

**拿同一個實際問題，追它在新框架裡由哪個元件處理。**

例如你要它明天接續整理一份文件，可以沿著剛才五個問題查：

| 要查的事 | 想找到的具體證據 |
|---|---|
| 指令 | 明天啟動時，會讀哪份任務要求？ |
| 工具 | 它是否有權限讀寫那份文件，結果回到哪裡？ |
| 記憶 | 今天做到哪裡，保存在哪個檔案或資料庫？ |
| 上下文 | 新對話或壓縮後，哪個步驟把進度讀回？ |
| 喚醒 | 明天由誰觸發，失敗會留下哪些紀錄？ |

這張表幫你把「支援記憶」「能自主工作」對到能查的行為，再決定還缺哪一段。

我後來在回覆裡寫過：「工具會過時，但透過工具累積的能力不會。」OpenClaw 曾經讓人開始理解 Agent，之後換成其他系統，先前學會的工具呼叫、記憶保存和工作接續，仍然有一部分用得上。

下次換框架，拿你目前最常失敗的一件工作，照這五個問題各找一個實際位置。找得到，你就知道哪些經驗可以延用；找不到的那一段，才是這次需要補學的內容。
