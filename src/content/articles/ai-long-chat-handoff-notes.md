用 Claude Code 改商品頁或寫程式，對話一拉長就常忘記前面的規格與禁詞。要讓新對話直接接手，先別只靠內建 `/compact` 硬壓，改拆成「交接摘要、專案筆記、進度備忘」三份分開留。

為免換對話就重講，我這陣子密集實測自己寫的開源外掛 `ctx-handoff-mod`。拿掉字數上限、改看「新對話真正需要甚麼」，我實測有效資訊從 50% 提高到 90% 以上。

## 只靠內建 /compact 或自己寫 Hook，為甚麼還是會漏條件？

長對話只靠內建 `/compact` 把當輪進度跟長期規矩壓在一起，易漏規格與禁詞。多視窗切換或離開一小時，又常碰到快取過期得重讀。

有人會用 Skill 做長度偵測與交接，也有人試著用 Hook 實作卻卡住。若要連同回合結束自動清空換對話、閒置主動保溫快取一起處理，可對照這兩種做法的差異。

| 項目 | 只靠 `/compact` 或手動重講 | 拆成三層交接（`ctx-handoff-mod`） |
|---|---|---|
| **當輪交接** | 歷史硬壓成一團，易漏規格與禁詞 | 分列已驗證／未驗證、失敗做法、原話限制與下一步 |
| **長期偏好** | 開新視窗常要重講部分習慣與修正 | 背景整理成專案筆記，新對話自動繼承 |
| **進度備忘** | 手動清空後忘記停在哪個步驟 | 自動記下停在哪，手動 `/clear` 也能接上 |
| **閒置保溫** | 訂閱制離開一小時快取過期需重讀 | 閒置約 50 分鐘保溫（最多 3 次），超時存交接單等你決定 |

## 把記憶拆成三層：當輪交接摘要、專案筆記與進度備忘

在 `ctx-handoff-mod` 裡，這三層記憶與防呆各司其職：

- **當輪交接摘要**：於 `/handoff panel` 開啟 `auto_handoff` 後，達 600k token 門檻會等當輪跑完，分列已驗證與未驗證改動、失敗做法、原話限制、已查的事與下一步。
- **跨對話專案筆記**：趁快取還在，背景只讀新增片段，把有理由的決定與習慣存進 `~/.claude/projects/` 並記次數（重複出現可轉規則）。
- **進度備忘與防呆**：記錄停在哪，手動 `/clear` 也能接上。若 AI 重複犯錯、沒驗證說完成或不用繁中也主動提醒。

需 Claude Code 2.1.287 版以上（目前此開源外掛屬實驗性功能），在終端機跑這兩行就能裝好：

```bash
claude plugin marketplace add cablate/ctx-handoff-mod
claude plugin install ctx-handoff@ctx-handoff-mod
```

裝好後在新對話輸入 `/handoff`，看到顯示上下文門檻與快取刷新狀態即代表成功：

```text
context 12034 / 門檻 600000（視窗 1000000）
快取刷新 on，本次閒置已刷新 0/3，計時器未啟動
```

要是還沒裝外掛或使用其他 AI 工具，準備換對話前可直接複製這段提示詞請 AI 寫交接單：

```text
請幫我整理這段對話的交接摘要，不要限制字數，以新對話能直接接手為準，分開列出：
1. 已驗證的改動 vs 還沒驗證的改動
2. 試過但失敗的做法（避免新對話重踩）
3. 我訂過的限制與規格（盡量保留我的原話）
4. 已經查到的事實與檔案位置
5. 接下來的下一步與目前停在哪裡
```

## 自動保溫會不會燒額度、把舊規則記回來？不想用怎麼退回？

手動刪掉的舊規則不會自己跑回來。`ctx-handoff-mod` 新增了墓碑機制且只讀新增片段，清理過的規則除非之後在新的對話片段又親口重提，否則不再寫回。

每次保溫只送小請求讀既有快取（約一般輸入價十分之一），適合 Claude 訂閱制與 1M 長視窗，也可搭內建閒置壓縮。

API key、Bedrock 或 Vertex 快取僅 5 分鐘，請跑 `/handoff refresh off`，底層消耗可看〈[Claude Code 額度為何越燒越快？](/articles/claude-code-token-drain-system-reminder/)〉。

想暫停保溫或切回內建 `/compact`，隨時可照這三種方式退回：

- **暫停離席刷新**：按 `/handoff panel` 頂部按鈕，或輸入 `/handoff away pause`。
- **切回內建壓縮**：在 `/handoff panel` 設定頁把 `auto_handoff` 開關關掉。
- **刪改專案筆記**：直接打開 `~/.claude/projects/` 裡的 Markdown 筆記檔修改或還原。

下次對話變長或準備開新對話前，先把要留的東西分開成「當輪交接摘要（已驗證與未驗證、失敗、原話限制、已查與下一步）」「跨對話專案筆記（偏好與修正）」與「進度備忘（停在哪）」，不要把整段對話只丟給內建 `/compact` 壓縮或每次重頭口述。
