用 Claude Code 或 Codex 做網站，功能改好、本機跑起來沒報錯，AI 接著問你要不要直接推上 `main`。這時候心裡很容易冒出一個念頭：整個專案就我一個人，真實用戶也才幾個，開分支跟 PR 未免太多餘；先推上去快速迭代，真的壞了再修就好，大不了重新部署退回上一版。

如果你的網站已經有正式環境、有真實用戶在使用，我不太認同「壞了再修」這種做法。要不要走 PR，不看團隊有幾個人或現在用戶多不多，看的是網站有沒有真實用戶，以及這次改壞了，重新部署救不救得回來。只要有真實用戶，就有維護使用體驗與信任的責任。

## 重新部署不是就回到上一版了嗎？

重新部署退回的是網站程式，資料庫裡被刪掉或改亂的資料不會跟著回來。照 Vercel 官方文件〈Instant Rollback〉的說明，Instant Rollback 能把正式環境快速退回之前的正式部署（免費 Hobby 方案能退回上一個部署，Pro 以上方案能退到任何曾經上過正式網域的部署）；但退回舊版時，環境變數（填在平台上的設定值）會維持原狀，確認退回的步驟也會提醒，目前或之前部署用到的外部 API、資料庫或 CMS 行為可能已經改變。

資料庫要救回來，靠的是備份。以 Supabase 為例，官方文件〈Database Backups〉寫明，每天自動備份涵蓋的是 Pro、Team、Enterprise 付費方案，把資料庫還原到特定時間點（PITR，時間點還原）也是付費方案的加購項目；免費方案的專案，官方建議自己定期用 Supabase CLI 的 `db dump` 匯出資料、另存一份備份。

推上 GitHub 的金鑰與密碼也一樣。照 GitHub Docs〈Removing sensitive data from a repository〉的說明，推上去的敏感資料如果是密碼、token 這類金鑰，第一步要撤銷或更換它；只把版控紀錄改掉再強制覆蓋上去（改寫 git 歷史並 `force push`）是不夠的，因為包含金鑰的舊紀錄（commit）仍可能留在別人下載或複製出去的專案（clone 或 fork）、GitHub 上的快取頁面，以及引用過它們的 PR 裡。

## 推之前把改動分兩類，預覽環境要接測試用的資料庫與金鑰

| 重新部署救得回的改動 | 救不回的改動 |
| --- | --- |
| **例子**：改畫面排版、文案或前端樣式| **例子**：動到資料庫、金鑰與密碼、登入與權限|
| **壞了怎麼辦**：用 Instant Rollback 退回上一個部署| **壞了怎麼辦**：重新部署救不回來|
| **推之前怎麼做**：直接推上 `main`| **推之前怎麼做**：先讓 AI 推到新分支、開 PR，在預覽環境試過再合併|

對 `main` 開 PR 時，Vercel 會建一個預覽部署（Preview Deployment）讓你先看改動；確定沒問題再把 PR 合併進 `main`，才建正式部署。

不過預覽環境必須先分開接測試用的資料庫與金鑰。Vercel 的環境變數可以分環境設定（Production、Preview、Development），推到非正式分支建立的預覽部署，用的是 Preview 那組環境變數；設定時要在 Vercel 的 Preview 那組環境變數填另一個測試用資料庫的連線與測試金鑰，和 Production 分開。如果兩邊填了同一個正式資料庫連線與同一把金鑰，你在預覽環境試跑刪除或修改功能時，動到的依然是真實用戶的資料。

推上 `main` 之前，也可以先把下面這段提示詞貼給 AI。

```
推上 main 之前，先告訴我這次改動有沒有碰到下面任何一項：
1. 資料庫：改資料表結構，或刪除、大量修改資料
2. 金鑰與密碼：新增、修改或搬動 API key、token、.env 檔
3. 登入與權限：誰能看到、誰能修改哪些資料
有碰到的話，不要直接推上 main，改推到新分支並開 PR，等我在預覽環境試過再合併。
```

## 只有自己用的小工具，或出問題能快速解決的人，不用走這套

沒有真實用戶、只有自己用的小工具，只有 `main` 分支也沒差，自己用得順手就好。這套 PR、CI 測試與分支保護，是幫沒走過正式開發流程、還不知道修改會引發甚麼連鎖影響的人，補上「寫得出來」到「安全上線」的落差；有經驗的開發者在規劃架構時就留了彈性與退路，遇到非預期的影響也能快速解決，對他們來說快速迭代、出事再修才成立。

下次 AI 問要不要推上正式環境，先問：這次改壞了，重新部署救得回來嗎？救不回來（動到資料、金鑰），就先走 PR、在預覽環境試過再合併。要把 `main` 設成只能走 PR，設定步驟可以看〈[AI 幫你 push 完，正式站也跟著改了？三個勾讓 main 只能走 PR](/articles/dont-let-ai-push-main/)〉。
