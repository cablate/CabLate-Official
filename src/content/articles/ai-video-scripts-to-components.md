以前用 Claude Code 或 Codex 做圖卡跟剪片，最煩的是腳本越寫越亂。前幾天盤點影片工作區才發現，文字震動、切半、砸落明明是同類動作，我竟然寫了 4 份重複程式，每次想微調都得一個個打開來改。

手機外框放大跟終端機打字放大更明顯。兩個都在做放大，程式卻跟各自的外框寫死在一起，想換個容器就得重寫；就算把整份腳本存成模板，換支風格不同的片一樣完全不搭。

## 借鏡 Radix UI，把「動作」跟「外框」拆開

後來我借鏡前端 Shadcn UI 底層的 Radix UI 思路，就像剪輯軟體一樣，把「怎麼動」跟「長什麼樣」拆開。動作元件只管動畫參數，外框元件只管容器外觀，兩者分開寫就能自由組合。

拿最常見的放大效果來說，放大動畫從此只寫一次。裡面要裝手機框、終端機、瀏覽器還是程式碼卡片，只要換一個參數就能套上去，不用為了換外框重寫整套動畫。

| 比較項目 | 整份存模板 | 動作與外框拆元件 |
| --- | --- | --- |
| 程式結構 | 動畫與外框寫死在同一份 | 動作管參數，外框管容器 |
| 換風格或容器 | 整體不搭，整段重寫 | 改一個參數套進新外框 |
| 複用累積 | 每做一部多一堆一次性檔案 | 能力沉澱成可組合工具庫 |

這樣拆省時間跟 token 只是順便，最重要的是「做對過的效果留得住」。就算未來模型降智，也不用每次重賭生成品質。這跟我寫〈[AI 第三次用同一個笨方法時，叫它停下來做工具](/articles/ai-build-tools-before-repeating/)〉一樣，重複踩的坑就該收成工具。

## 直接複製給 AI 盤點舊腳本的提示詞

把舊腳本拆成元件不用自己翻檔重構。打開剪片工作區，把下面這段提示詞貼給 AI 就能一次整理。貼之前建議補一句「先列出盤點清單讓我確認，同意後再動手改檔」，免得它直接改壞正在用的腳本。

```text
請全面盤點過去 AI 剪輯過程累積的中間產物（HTML、JS、Python、動畫、特效腳本等），將值得複用的能力整理成標準化、可參數化、可組合的工具庫。

參考 Radix UI 的 Composable Primitives 思想，但不侷限於此，僅是做一個標誌性參考，應依照我們的剪輯與常用工具特性，選擇最合適的抽象方式。

設計優秀的統一調用介面與輸入輸出規範，為每項能力提供明確的用途描述、適用情境、參數及使用範例，讓未來 AI 能直接調用與自由組合，同時又易於維護與最佳化既有能力。
```

## 重構完怎麼驗收，並指進工作區規則檔

AI 跑完盤點重構先別急著收工，為了確定這套元件庫在往後的剪片對話裡真的接得上，我現在的檢查順序固定走這三步：

1. 確認長出元件清單：每個元件都要附上用途、適用情境、參數與使用範例，AI 下次呼叫才看得懂。
2. 實測換參數套新外框：挑一個動作元件，改一個參數套進別的外框，動畫能直接跑通才算及格。
3. 把清單路徑指進規則檔：新對話沒有上一輪記憶，工作區規則檔沒寫清楚元件清單路徑，AI 一樣找不到。

## 元件庫變大後，防呆重點是不讓 AI 偷懶硬套

元件庫順手之後，很快會碰到下一個坑。工具清單一長，AI 很容易不管新片節奏合不合，硬把現成元件塞進去交差，做出來的影片越長越像。

讀者 `@pan_0709` 的做法很實用，我直接補進同一份規則檔裡：「元件只是參考，不合就不硬套，創意優先」。讓 AI 先看過現有元件，順手才用，不搭就直接重寫，才不會把創意一起鎖死。
